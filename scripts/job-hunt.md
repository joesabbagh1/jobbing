Daily job hunt for the jobbing app (you are in its folder). Work on your own; nobody is there to answer questions. Your job is only to find new postings and save them: don't score, apply or write anything else.

Who it's for: read the search profile with `sqlite3 data/jobbing.db "select value from settings where key='searchProfile'"`. In short: a Cloud / DevOps / SRE / Platform / DevSecOps / cloud security engineer, about 3 years of experience, open to anywhere in France (location doesn't matter), looking for a permanent contract (CDI) starting February 2027. Junior to mid-level only.

0. Indeed alerts: run `npm run -s indeed:alerts -- data/ranking/<today's date>-indeed.json`. It writes the new Indeed job alert emails from the user's Gmail as text (Indeed blocks automated access to its site, so this is the only way in). For every job in them that fits step 2, look for the same posting on the company's career site or another job board with a web search, and use that page's URL if you find it. Otherwise keep the `https://fr.indeed.com/viewjob?jk=…` link and put the email's snippet in "description", starting with "From an Indeed alert email (full posting not readable): ". Add them to the same found.json as the rest, and give them the location and date from the email. Once `hunt -- add` has run, mark the emails handled with `npm run -s indeed:alerts -- done data/ranking/<today's date>-indeed.json`.
1. Search the web for postings published in the last 14 days. Cover the sites the app's own search doesn't read: HelloWork, Welcome to the Jungle, APEC, Indeed France, Free-Work (CDI only), Jobteaser, and company career pages on Teamtailor, SmartRecruiters, Workday, Taleo and similar. Use French and English queries, for example "ingénieur DevOps CDI", "ingénieur cloud AWS CDI", "SRE CDI France", "ingénieur DevSecOps CDI", "platform engineer Kubernetes CDI", "ingénieur sécurité cloud CDI".
   Most of your searches should be limited to one career site at a time, because general searches rarely reach company career pages. Combine each of these with a few keywords (DevOps, SRE, Kubernetes, cloud, DevSecOps, platform): `site:jobs.world.luccasoftware.com`, `site:teamtailor.com`, `site:recruitee.com`, `site:jobs.lever.co`, `site:jobs.ashbyhq.com`, `site:boards.greenhouse.io`, `site:jobs.smartrecruiters.com`, `site:apply.workable.com`, `site:welcometothejungle.com/fr/companies`, `site:jobaffinity.fr`, `site:taleez.com`, `site:flatchr.io`, `site:digitalrecruiters.com`, `site:myworkdayjobs.com`, `site:hellowork.com`, `site:free-work.com`, `site:jobteaser.com`.
   When a company that hires for these roles in France has its career board on one of the boards the app can read, add the board to the app's watchlist so it's checked automatically from then on: `sqlite3 data/jobbing.db "insert or ignore into companies (name, ats, slug, discovered_from) values ('<Company>', '<ats>', '<slug>', 'claude')"`. The ats and slug come from the board's address: lucca for jobs.world.luccasoftware.com/<slug>, teamtailor for <slug>.teamtailor.com (or the career site's own host, such as careers.acme.fr, when it is a Teamtailor site), recruitee for <slug>.recruitee.com, lever for jobs.lever.co/<slug>, ashby for jobs.ashbyhq.com/<slug>, greenhouse for boards.greenhouse.io/<slug>, smartrecruiters for jobs.smartrecruiters.com/<slug>, workable for apply.workable.com/<slug>. List the boards you added under "Boards added". Cover all of France equally, plus remote roles open to France.
2. Keep a posting only if it is a single, real job page (not a search results page or an aggregator listing), a permanent role (CDI, not freelance, internship, apprenticeship or fixed-term), in France or remote from France, and not senior, lead, staff, principal, manager or architect level. Skip Thales and its subsidiaries.
3. Check that each page is still open by fetching it, and note the exact title, company, city and publication date. Avoid jobs already in the app: `sqlite3 data/jobbing.db "select company, title from jobs where company like '%<name>%'"`.
4. Aim for quality over volume: around 10 to 30 good postings a day is plenty. Stop after about 40 minutes of searching.
5. Write `data/ranking/<today's date>-found.json` as `[{"url", "title", "company", "location", "postedAt": "YYYY-MM-DD", "description"}]`. Put the job's text in "description" only if you read the full posting; leave it out otherwise. Then save them with `npm run -s hunt -- add data/ranking/<today's date>-found.json`.
6. Reply in Markdown. The first line must be a plain one-line headline like "Found 18 new postings, 12 added." Then list the added jobs (company, title, city, site, and "via Indeed alert" where it applies), briefly how many were already known or filtered out and how many Indeed alert emails were read, and the "Boards added" if any.
